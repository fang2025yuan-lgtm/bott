# Bug fixes, QR check-in hardening, and Super Admin CRUD for UFQ EventBot

This change addresses ~20 bugs across the data layer, handlers, and infrastructure while adding two new feature surfaces: a full Super Admin management panel (user/event/club CRUD with pagination) and club-scoped event management for presidents. The approach is additive — existing patterns (session-per-function, FSM-driven flows, inline keyboards) are extended rather than restructured. The security posture of the QR check-in flow improves meaningfully: PIN generation moves to `secrets`, the hash doubles in length, the notification targets the verified ticket owner, and `check_in_enabled` gates scanning.

**Watch for:** `update_event_field` accepts arbitrary attribute names validated only by `hasattr`, which could allow writing to relationship or internal attributes (confirmed). The `create_ticket` retry loop calls `session.rollback()` mid-session but continues using the same session object, which may leave it in an inconsistent state depending on the driver (likely). The deep-link hash parsing splits on `_` and takes `parts[3][1:]`, which silently truncates any hash that itself contains underscores (confirmed).

## High-level view

The security-sensitive QR check-in path is substantially improved: PIN generation uses `secrets`, the hash is 32 hex chars (was 16), `check_in_enabled` must be true for scanning to proceed, and the notification targets the actual ticket owner. However, the deep-link parsing assumes the security hash contains no underscores — safe for hex today but fragile if the hash format changes.

A new `update_event_field` utility exposes `setattr`-based writes gated only by `hasattr(event, field_name)`. The callers control what field names reach it through their own validation, but the CRUD function itself is a footgun if reused elsewhere.

The deploy script backs up the SQLite database before nuking the old directory, but the backup lands in `/tmp` — volatile storage. And the restored database won't have the new `event_date`/`location`/`check_in_enabled` columns since there's no migration path.

`_show_clubs` accesses `club.users` (lazy relationship) after the session that loaded the clubs has closed. This will crash at runtime with `DetachedInstanceError`.

## QR check-in: notification targeting and middleware bypass

The deep-link handler no longer imports `bot` from `bot.main` (circular import hazard) and instead receives it via aiogram's dependency injection. `verify_and_checkin` now returns a 4-tuple `(success, msg, user_full_name, user_telegram_id)` where `user_telegram_id` is the actual ticket owner's Telegram ID resolved from the database. The handler logs a warning if the URL's `user_tg_id` disagrees with the real owner and sends the notification to `real_user_tg_id`. This closes a spoofing vector where an attacker could have directed notifications to an arbitrary user by manipulating the deep link.

The middleware bypass for `/start chk_` fires before the deep-link handler validates the token. An unauthenticated user who hasn't joined mandatory channels can reach `verify_and_checkin`, where scanner permissions block them. But the subscription check is bypassed for _any_ message starting with `/start chk_` regardless of what follows — a minor concern if other handlers ever match that prefix.

## Deep-link hash parsing fragility

The deep-link format is `chk_E{event_id}_U{user_tg_id}_S{hash}`. Parsing splits on `_` and takes `parts[3][1:]` to strip the `S` prefix. Since `generate_security_hash` produces hex characters (no underscores), this works today. But the split uses no `maxsplit`, so a hash containing `_` would be silently split across multiple parts. A future change to the hash encoding (e.g., base64url) would break parsing without a test failure to catch it.

## `create_ticket` retry loop and session state

```python
for attempt in range(max_attempts):
    pin = generate_pin()
    ...
    session.add(ticket)
    try:
        await session.flush()
        break
    except IntegrityError:
        await session.rollback()
        if attempt == max_attempts - 1:
            return None, "PIN generatsiya qilishda xatolik..."
        continue
```

After `session.rollback()`, the session's identity map is cleared. The `user` object fetched earlier in the same session may be expired or detached. On the second iteration, the code eventually accesses `user.club` (for the ticket image) after the identity map was cleared. In async SQLAlchemy, this could raise a `MissingGreenlet` error because lazy loading requires a sync greenlet. This path only fires on PIN collision (rare with 10^6 possible PINs), making it hard to catch in casual testing.

## `update_event_field` — open setattr surface

```python
async def update_event_field(event_id: int, field_name: str, value):
    if not hasattr(event, field_name):
        return False, "Noto'g'ri maydon nomi"
    setattr(event, field_name, value)
```

The callers map user-chosen fields through a `field_map` dict, so values reaching this function are constrained today. But the CRUD function itself imposes no allowlist — it would write to `id`, `created_by`, `club_id`, or relationship attributes without complaint. If another handler reuses this function without its own mapping layer, it becomes a privilege escalation path. Adding `ALLOWED_FIELDS = {'title', 'description', 'post_link', ...}` with a check at the top of this function eliminates the risk.

## Detached instance in `_show_clubs`

`get_all_clubs()` runs inside `async with AsyncSessionLocal() as session:` and returns the results. The session closes when the context exits. In `_show_clubs`, the code accesses `club.users` (a lazy-loaded relationship) to get `len(club.users)`. With the session closed, this raises `DetachedInstanceError`. The fix is adding `selectinload(Club.users)` in `get_all_clubs()` or replacing the member count with a dedicated count query.

## Missing schema migration for existing databases

The model defines `event_date`, `location`, and `check_in_enabled` on `Event`. The deploy script restores the old SQLite database via file copy. SQLAlchemy's `create_all` only creates tables that don't exist — it does not add columns to existing tables. On first access to these columns after an upgrade, SQLite will raise `OperationalError: no such column`. Since the project doesn't use Alembic, the deploy script needs `ALTER TABLE events ADD COLUMN` statements for the three new columns, or the bot startup should run a migration check.

## Deploy script backup durability

The database backup goes to `/tmp/ufq_events_backup.db`. On most Linux distributions, `/tmp` is cleared on reboot (often tmpfs). If the server reboots between the backup step and the restore step — possible during a failed deploy — the backup is lost and the new deploy starts with an empty database.
